# Sales copilot step

1. Read the active project's status before other artifacts. Classify the founder's message as a reported result (a sent message, reply, call outcome, or post result), an explicit request (a named person, contact, post, Reel, call, comment, week planning, offer, or positioning), or no specific request. A reported result goes to step 8 first. Project: use `workspace/config.yaml` `active_project` unless the request names a contact, outlet, or project fact that exists in exactly one other project's workspace; then work in that project for this turn without editing config. If still ambiguous, ask one question. A message that reports a result and also asks for an asset gets the asset in the same turn; record the result after the founder confirms it (step 8). Recording never delays the asset.
2. Explicit founder intent always selects the matching specialist in the same turn, using `explicit_intent_routes` in `core/workflow-catalog.yaml` as the single routing table (for example: a follow-up on a named contact goes to `handle-follow-up` without a pre-existing pending action; a Reel or face-vs-faceless test goes to `draft-reel`; "Wochenstart" or "Was steht an?" goes to the weekly mode of `sales-next`). Lifecycle state (overdue experiment review, current outreach lane, pending queue, reached `review_after`) never blocks an explicit request. Only schema v2 or missing profile or project context routes to `sales-setup` first. When `review_after` in the project's `project.md` is reached, add one `[PRÜFEN: Projektstand vom <updated_at>]`. `review_after` in other artifacts (evidence, positioning, experiments, contacts) adds no marker. A private message after a public exchange, or the first written message after an in-person conversation, is `first_touch`. `received_reply_or_comment` answers inside the same thread, and it applies even without a queued action.
3. Without explicit intent, resolve the lifecycle through `core/steps/route.md`. When it returns a due pending action, preserve its `action_id` and `target_ref` and do that action. When no action is due and `workspace/projects/<slug>/pipeline.md` is missing or belongs to a past ISO week, run the weekly start in `core/steps/pipeline.md`; it makes an overdue experiment-review decision once and resets `activity.experiment_review_at`, then perform its first action in the same turn. Otherwise use the lifecycle result. A warm-comment draft does not clear another outreach lane or pending action.
4. Load only the artifacts and references required by that specialist. For drafting, follow-up, and call work, pick one persona (`media-podcasts`, `creators-influencers`, `ngos-civic-orgs`, `funders-foundations`, `buyers-users`, `connector`, or `other`) and load only the needed sections of `knowledge/personas/<persona>.md` (usually `## Ask ladder`, `## Give-first asset`, `## Message skeleton`, or `## Call kit`), plus `## Gemeinsame Belegzeilen` and `## <persona>` from `workspace/projects/<slug>/personas.md` when present. `connector` and `other` have no persona file: `connector` uses `knowledge/channels/personal-network.md` (`## Intro kit`) and the `Connector after an intro` touch-plan row; `other` uses the `## Drafting card` in `knowledge/strategies/first-touch.md` and the default `LinkedIn DM` row. `buyers-users` takes its ask ladder and give-first asset from the project's `icp.md` and `positioning.md`. Do not make the founder repeat current workspace facts.
5. Perform the specialist work in the same turn and always return a usable asset per `knowledge/foundations/human-writing.md`, section `Draft-first and gap markers`. Missing input becomes inline markers plus at most three check items under `Dein manueller Schritt:`; it never replaces the asset. Only the stop cases listed there return no draft. Apply the specialist's evidence gates and asset rules internally, but let the copilot's four-section presentation contract take precedence over the specialist's direct-invocation output shape.
6. Preserve the specialist's evidence, voice, platform, relationship, and safety boundaries. External sending, posting, scheduling, submission, signing, and payment actions remain manual.
7. Return the four sections. `Nächste Aktion:` is one concrete action in at most two sentences; a specialist's decision line (`Touch: …`, the Reel test line, the call mode and target) is that action, with no rationale paragraph. Only the weekly modes open with the board's scoreboard line, copied verbatim with its markers. Lifecycle-routed turns may add one sentence naming one deferred item; explicit-request turns add none. Name people by their display name. Never show a skill name, an internal file path or label (e.g. `Entwurf 0`, `Offener Prüfpunkt 2`), a duplicate wrapper, a `Why:` block, or a second output shape. When a message to another recipient must go first (e.g. a Träger confirmation), quote it in full as item 1 of `Dein manueller Schritt:`.
8. After the founder reports the result, record the real action or interaction before continuing to another asset, and update the board row. Resolve or cancel only the selected pending action; never clear unrelated queue entries. A result report does not trigger the weekly start by itself.
