# Sales copilot step

1. Read the active project's status before other artifacts and identify whether the founder expressed a more specific current intent.
2. Resolve the next lifecycle gate through `core/steps/route.md`. When it returns a pending action, preserve its `action_id` and `target_ref`. Explicit work on a real reply, scheduled call, requested offer, positioning problem, or public post may select the matching specialist only when its gate is satisfied.
3. Load only the artifacts and references required by that specialist. Do not make the founder repeat current workspace facts.
4. Perform the specialist work in the same turn when the evidence is sufficient. Apply its evidence gates and asset rules internally, but let the copilot's four-section presentation contract take precedence over the specialist's direct-invocation output shape. Do not return a skill name, duplicate wrapper, or internal `Why:` block as the finished result.
5. If one material input is missing, make obtaining or confirming that input the single action and keep the request concrete.
6. Preserve the specialist's evidence, voice, platform, relationship, and safety boundaries. External sending, posting, scheduling, submission, signing, and payment actions remain manual.
7. Return one next action, one finished asset or smallest honest input request, one manual founder step, and the exact result the founder should report back.
8. After the founder reports the result, record the real action or interaction before continuing to another asset. Resolve or cancel only the selected pending action; never clear unrelated queue entries.
