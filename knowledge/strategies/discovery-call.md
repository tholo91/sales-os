# Discovery call

The core question is whether a recurring situation exists strongly enough to justify change.

Ask about:

1. The last concrete occurrence.
2. The current workaround and people involved.
3. Consequences, frequency, and urgency.
4. How a decision would be made.
5. What would have to be true to switch, test, or pay.

When the situation is consequential, also understand the decision-maker's internal stakes:

- “What would need to be true for you to defend this internally?”
- “Who owns the downside if the change does not work?”
- “What changes for your role if this is solved, or if it stays as it is?”

Use these answers to understand risk, ownership, and desired outcomes. Do not turn assumed identity or career motives into messaging claims.

Do not lead the witness, convert every complaint into validation, or demo before understanding the current workflow.

## When resistance appears

Treat pushback as information about the decision, not as a cue to pitch harder. Use this sequence:

1. Label the concern: “It sounds like changing the current process is the bigger risk.”
2. Mirror a meaningful phrase from the answer, then pause.
3. Ask one calibrated question: “What would need to be true for a small test to make sense?”
4. Summarize the constraint and check it: “So the issue is timing, not whether the problem exists. Did I get that right?”

Do not stack several questions or use negotiation language to force a commitment. The goal is a more precise decision signal: a test, a changed condition, or an explicit no-fit.
